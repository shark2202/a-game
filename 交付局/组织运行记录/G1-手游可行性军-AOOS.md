# G1-手游可行性军 · AOOS v0.1

> **Goal（Locked）**：对「单人（高级程序员，不熟游戏行业）+ AI Agent 协作，约半年内（至 2027-03）通过手机游戏获得正净收入」做出可决策的可行性论证。
> **AC（每条缺一不算完成）**：① 报告含四板块且关键结论带来源锚点（出处+读取时点）：市场与赛道（规模/独立开发者细分/盈利分布）、变现与平台经济学（IAP/广告/买断/抽成/买量成本基准）、能力与资源匹配（单人+AI 的现实案例与周期）、风险与机会地图（版号/合规/平台政策/AI 内容政策/竞争密度，国内与出海两路）；② 明确三选一建议（进/不进/改道）+支撑推导；若「进」附最小可行路径（类型/范围/里程碑/预算/时间盒），若「改道」附 ≥2 个备选方向；③ 一切事实断言可溯源（no-memory-citation：抓取核实、截断标注、存在性断言带时点）；④ fresh verifier 锚点抽查 ≥50% + AC 逐条合规，结论只构成 Pre-Verified；⑤ 全部产出落盘 projects/g1-手游可行性/。

## 二、Role 要点

- **coordinator**：responsibility＝任务书起草与回灌、三线综合、三选一建议必须由三线数据显式推导（防夹带倾向）；authority＝写任务书/AOOS/注册表/账本/综合稿；constraints＝不改 researcher 文件内容、无 active 化裁决权、产物经 fresh 复核。
- **researcher ×3**：responsibility＝单线「溯源→精读→落盘」，每条结论带锚点（URL+读取时点），成功与失败案例并重（各 ≥2，防幸存者偏差），截断显式标注；authority＝只读外部+只写自己文件；constraints＝禁凭记忆引用、不下投资级结论（结论归综合）、报告 ≤40 行。
- **verifier**：responsibility＝锚点抽查（重抓来源比对支撑性）+AC 合规；constraints＝只报告不修复、与产出者无共享上下文、结论只构成 Pre-Verified、报告 ≤50 行落盘。
- **hostile-reviewer**：responsibility＝以推翻报告为任务；constraints＝只读、判决三选一（ACCEPT/notes/REWORK）、报告 ≤40 行落盘。

## 四、DecisionRecord（事前）

**决策：成军写作军论证「单人+AI 半年内手机游戏盈利」的可行性，以报告支撑进/不进/改道决策。**

**维度（成功怎么判）**：报告经 fresh 验证+敌意审查+人类终审；goal-keeper 能据其做出明确决策；锚点抽查通过率 ≥90%；三线各有失败/中位案例（无幸存者偏差）；事后回看报告对关键变量（时间盒现实性/变现门槛）的判断与 G2 实况的偏差可追踪。

**死法（概率×代价），6 条**：
1. **幸存者偏差**（只看成功案例→过度乐观）→ 对策：三线各含 ≥2 失败/中位案例为 AC 强制项；hostile-reviewer 专攻维度。
2. **数据失真/过时**（手游市场时效性强，凭记忆或陈旧数据）→ 对策：PAT-001 逐字执行（抓取核实+读取时点+截断标注）；verifier 锚点重抓比对；关键数据交叉源 ≥2。
3. **论证-决策脱节**（报告好看但不可决策）→ 对策：AC② 三选一+触发条件+最小可行路径；hostile-reviewer 攻「建议可决策性」。
4. **派发失败**（本环境已知：6 败 3 成基线）→ 对策：PAT-007（结论落盘+一行摘要）；每线轻载（报告 ≤40 行）；失败重试一次，再败即拆载或降级为 coordinator 会话内直接执行研究（保留 fresh 验证门不降）。
5. **协调者失效预演（必含）**：coordinator 综合时夹带倾向（把「想进」写入推导）或跨线串染（把 A 线数据写错归属）→ 对策：三选一建议必须显式引用三线锚点链；hostile-reviewer 攻「结论是否被数据支撑」；综合稿与三线文件同盘可比对；终审在人类。
6. **外部资源不可得**（付费墙/搜索受限）→ 对策：降级链＝权威免费源→公开二手源（标注二手性+原文指针）→如实标注「数据天花板」并写入报告限制节；数据不可得本身作为论证输入（scout 精神：材料上限改写结论置信度，不硬凑）。

**可逆性**：全部新增文件；本体回退＝删除 projects/g1-手游可行性/ 与本 AOOS+注册表行；已扩散引用（账本行、缓存条目、G2 可能的输入）需逐一回收。

**事前 Prediction**：
- P1：至少一条关键市场数据（如独立开发者盈利分布）无免费权威源，须二手源+标注降级。
- P2：至少一次 researcher/判定者派发失败需重试（环境基线），但轻载拆线后成功率应显著高于 6 败 3 成基线。
- P3：敌意审查至少击中一处幸存者偏差或数据时效问题（REWORK 或 notes）。
- P4：三线结论将出现张力（如「市场大盘大」vs「单人窗口窄」），综合须显式仲裁而非平均——仲裁逻辑本身会被敌意审查攻击。
- P5：最终建议为「有条件进」（条件＝范围裁剪+时间盒+早期止损点）而非干脆进/不进。

## 五、Runtime Loop + 降级拓扑预置

标准循环（写作军裁剪：M0→M1 试点（波1）→M2 批量（波2）→综合（波3）→M3 验收→M4 学习解散）。

- **限流类**（派发超时/零产出 >10 分钟）：重试一次→再败拆载（单线拆为两半）→仍败则 coordinator 会话内执行该线研究，fresh 验证门不降。
- **过滤类**（外部抓取不可得）：降级链见死法 6；全部关键源不可得 → 停波留痕上报（不硬凑）。
- **超界类**：敌意审查击穿 >10 或判决 REWORK×2 → 停机留痕 T3a 上浮；锚点抽查通过率 <70% → 整线返工。
- **协调者不可达**：researcher 就地停线留痕（HALTED 于波次状态.md），等待成军官回合。
