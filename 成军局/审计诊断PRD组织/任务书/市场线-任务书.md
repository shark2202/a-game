# 市场线任务书 · 审计诊断PRD组织

## 一、角色与边界（继承 AOOS §二）

- **responsibility**：单线"溯源→精读→落盘"——外部市场证据抓取核实 + 需求侧输入（买方画像、付费意愿、竞争格局）。你的产出是 PRD 需求锚定与可行性判定的市场侧唯一来源。
- **authority**：只读外部源（网页/公开报告）；只写 `D:\bytecoder_ai\成军局\审计诊断PRD组织\市场线\市场线-研究报告.md`（该文件不存在则创建；1a 写试点节，1b 续写全量节——**不得改写试点节已定稿内容**，发现试点节错误时在冲突记录节并列登记）。
- **constraints**：禁凭记忆引用（每条结论须实际抓取核实）；存在性断言标注读取时点（ISO 8601）；截断显式标注（截断位置+原文长度）；价格/时间线类数字必须给出处原文口径；与附录O记载冲突时双方口径并列，不静默改写。

## 二、商业背景

本组织为附录O第一段商业主线产出 PRD："对 agent 规模部署企业做组织级审计诊断（AOOS 合规性/委托图/验证额度盘点/监督通道缺口）"，付费锚定买方已验证的审计/合规预算。附录O（`D:\bytecoder_ai\ai-native组织理论.md` 约第 5074–5101 行）记载的锚点口径是**待核实的种子假设**，不是事实——你的任务就是把这些锚点从"书中记载"变成"已核实的外部证据"，并诚实记录偏差。

## 八、试点教训回灌（1a 工艺检查结论，波次1b 生效）

coordinator 检查判定：四点工艺标准达标。四条教训回灌 1b 任务：
- **L1 获取链路**：本环境 WebSearch 连续返回空结果、WebFetch 间歇 503——1b 直接以 Bash curl（DuckDuckGo HTML 版/Bing）+ WebFetch 目标页直抓为主通道，跳过 WebSearch 重试预算浪费；每条降级获取照旧标注。
- **L2 源质量分层**：沿用试点节做法——官方页面沉默本身作为证据（注明"官方页面无X内容"）；从业者转述需两独立源相互印证；商业利益源显式标注"利益相关"并降权为三角印证第三源。
- **L3 低可信信号处置**：不可核实的跟踪器声称（如 Walko "working draft released"）登记为低可信度信号并列，不采信为结论；孤证惊人性声称（如"SOC for AI 已发布"）经搜索引擎交叉验证后判不可信并列登记——1b 对 ③–⑧ 同样适用。
- **L4 数字口径分层**：价格类一律分层报告（总花费 vs 纯服务费；一次性 vs 年度重复；分机构层级 boutique/national/Big 4），并保留"与种子口径对照"节。
- **L5 增量落盘（1b 超时事故教训）**：每完成**一项**锚点核实（含其来源与对照）即用 Edit/Write 写入报告对应位置，禁止全部完成后一次性写入——单次会话崩溃时已完成项不丢失。
- **L6 时戳取法**：所有"读取时点"须以 Bash `date +"%Y-%m-%dT%H:%M:%S%z"` 系统时钟现取（每批次抓取前后各取一次即可），禁止凭估计写时戳（本环境存在代理自报时戳与系统时钟偏差的已记录实例）。
