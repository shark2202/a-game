**维度 1：AOOS 合规性**

- **需要客户方什么输入**：客户的子组织/agent 编排规范文档（AOOS 或等价物：编排配置、agent 注册表、任务书模板、DecisionRecord 样例）；若客户无此类文档，则改为结构化访谈重建（访谈提纲按元组织 §10.1 七节骨架逐节提问）。
- **检查什么**：对照成军局规范的三层检查物——①§10.1 子组织 AOOS 模板七节骨架（Actor Registry / Role 四要素 responsibility-authority-constraints / 任务分解波次 / DecisionRecord / Runtime Loop 含降级拓扑预置 / 人类终审栏 / 事后校准）；②§6.1 政策继承块逐条（采样率显式、停机留痕、存在性断言带时戳等 12 条政策的客户侧等价物）；③§6.2 每次成军验收五项（DecisionRecord 齐 / AOOS 完备 / 知识落盘格式 / fresh 验证 / 学习闭环）。
- **产出什么交付物**：AOOS 合规性对照表——逐节逐政策给出 {具备 | 部分具备 | 缺失} 判定 + 差距描述 + 建议修复动作（引用元组织对应条款编号）。
- **理论依据**：`ai-native组织理论-元组织.md` §10.1（七节骨架模板）、§6.1（政策继承块）、§6.2（验收清单）、第二章 T8（Constraint Before Procedure）/T16（DecisionRecord 状态机）。

**维度 2：委托图**

- **需要客户方什么输入**：权限与授权配置（agent 工具权限、API scope、审批流配置）、agent/人 actor 清单、委托链上各环节的文档或访谈（谁授权谁、谁对谁负责、证据留存在哪）。
- **检查什么**：①治理链十环逐环落位——Principal→Policy→Delegation→Authority→Responsibility→Assignment→Action→Evidence→Accountability→Liability（理论 16.2），找出断环（无承载者的环节）；②Authority ≠ Capability 检查（16.1；附录N 映射表 Hurwicz 激励相容行：能做 ≠ 能可靠得到）；③不可委托内核是否被委托给 AI——问责、终极责任、Purpose 合法性、解释义务（元组织 T14；理论 36 章）；④多跳委派耗散点——Principal→Manager-AI→Worker-AI 链上每一跳的转述与自动填补（理论 50.2 缺口②，最大空白；Artifact-only 传递是否执行，50.3 贯穿机制）。
- **产出什么交付物**：委托图 L 盘点图 + 断链/断环清单（逐环标注承载者、证据物、断点风险等级）。
- **理论依据**：理论 16.2（治理链十环）、16.3（治理基本对象）、7.2（Delegation）；附录F 提案三（"执行前审 L（委托图）——审设计比审执行便宜一个数量级"、授权图 diff、P-18 前置必检）；理论 50.2 缺口②；元组织 T5（Authority Is Delegated）/T6（Responsibility Must Be Explicit）。

**维度 3：验证额度盘点**

- **需要客户方什么输入**：AI 产出量与人工验证工作量的数据（工单/审阅/签核记录）、抽样率设定文档、最近额度校准记录、透支/回滚事件史；无量化数据时按 49.7 六问做访谈估算并标注估算属性。
- **检查什么**：①判断带宽不等式实测——(1−p)×R_ai ≤ R_h（理论 49.1）：客户实际的人工必验负载是否已超人类判断速率；②五指标读数——TTA（新 Actor 获实质授权时间）/ VOR（验证开销比）/ PTR（免检直通率）/ RI（无 AI 降级运行能力）/ CDR（额度衰减率）（49.5）；③49.7 可操作审计项六问逐条（PTR 与抽样率配对？最近校准何时何人？"看起来可信但未验证"的采信识别？RI 是否实测？Rationale 人类判断比例？6 个月透支事件史？）；④加速错觉风险——高可信表象让额度看起来比实际更多（48.2 证据表第三行 arXiv:2605.23177，中强度；49 章不变量）。
- **产出什么交付物**：组织资产负债表（49.4 资产四项/负债四项）+ 五指标读数表 + 带宽不等式违反判读（哪些产出流已处于"假运行"——元组织 T15：超限即假运行）。
- **理论依据**：理论 49 章（49.1 不等式、49.4 资产负债表、49.5 指标、49.7 审计项）、48 章（48.2 证据分级、加速错觉机制）；附录N（Heckman 选择偏差→验证额度天然自选择样本——抽样的第一性模型警示）。

**维度 4：监督通道缺口**

- **需要客户方什么输入**：现有监督/告警/审批流配置、on-call 与升级路径安排、事件响应记录、人类终审的实际发生记录（谁在什么触点出场）。
- **检查什么**：①监督三通道齐备性——事实通道（拉：可查询的组织事实仪表）/ 例外通道（推：仅 Blocked 超阈值、越权、不可逆决策、否决四类事件可打扰委托人）/ 抽样通道（定期：目标对齐与产出质量双维）（附录F 提案三构件③——判断带宽不等式的工程化）；②48.4 三个组织级断裂——验证者悖论（证据齐全没人真懂）、组织记忆回声室（记忆退化为 AI 输出自我引用）、依赖形态转换（可迁移人类专家→不可迁移外部系统）；③48.6 组织能力审计六问（委托是否同步抬高 AC？谁具备验证判断力？接管路径真实演练过？Rationale 人类比例？独立判断训练时长>0？撤回全部 AI 能否降级运行？）；④human 接管路径不过期——P-11 / I-INDEP、Safe Halt 优先于继续执行（理论 50.3 贯穿机制、36.3 降级拓扑）。
- **产出什么交付物**：监督通道缺口报告——三通道逐个 {有 | 部分 | 无} + 断裂点定位（哪一断裂、机理、后果）+ 缺口修复优先级。
- **理论依据**：理论附录F 提案三（监督三通道、四类例外事件）、48.4（三断裂）、48.6（审计六问）、36.3（降级拓扑/Safe Halt）、50.3（Human 接管路径不过期）；元组织 §5.4（四触点）、C5（验证额度+带宽总账）。

## 二、资源面判定

**判定：有条件可行。**

单人形态可以交付第一段（0–12 个月，附录O 一），但收入上限被判断带宽不等式结构性封顶——**单人供给是一门有天花板的生意，规模化必须以 R/I 抽样配额落地 + 第二判断者就位为前置**（附录O 三硬约束⑤）。可行性成立与否取决于三个条件（均为假设清单高/中代价项）：定价落审计费层成立（付费意愿零锚待实测）、第二判断者培养期内单人带宽不被击穿、单项目周期经试点实测后与排期假设相容。

### 2.1 封顶公式（附录O 三硬约束⑤）

```
收入上限 = 单人终审带宽 × 费率 × 排期约束

其中：单人终审带宽受判断带宽不等式封顶（理论 49.1）：
      (1 − p) × R_ai ≤ R_h
      （p = 可形式化比例；R_ai = AI 产出速率；R_h = 人工逐件判断速率）
```

本组织自身即元组织运行：诊断项目中 AI worker 的产出（四维度盘点草稿）汇聚到单人终审（元组织 §5.4 四触点；T15 判断带宽不等式；C5 带宽总账——多项目并行时监督负载合并记账，超限先降并发再降标准，**不降验证标准**）。提高 p（模板化、R/I 抽样配额）是唯一能抬高不等式右侧可用带宽的杠杆——这正是"规模化前置 = R/I 抽样配额落地"（附录O 三硬约束⑤）的机理。

### 2.3 带宽核算

**单人终审带宽的构成**：每个诊断项目消耗的判断带宽 = 四维度终审 + 敌意审查结论复核 + DecisionRecord 事后校准三部分（元组织 §5.4、C4 门控、§10.2 校准栏）。单项目的具体人时数**无文档锚点、无市场锚点**——按数字纪律不给出虚构值，登记为假设 M1（中代价：影响排期/定价，试点批次首案实测回填）。

**收入上限敏感性表**（锚点单价 × 年结案项目数 N；N 为无锚假设变量，敏感档位呈现）：

| 年结案项目数 N（假设） | 单价 $18k（锚① Type II 下沿） | 单价 $50k（锚①③ 审计费层中带） | 单价 $90k（锚① Type II 上沿） |
|---|---|---|---|

| 4 | $72k | $200k | $360k |
| 6 | $108k | $300k | $540k |
| 8 | $144k | $400k | $720k |

- 计算仅用锚点单价做乘法；N 档位非核实值。**第二段启动 gate 要求第一段 ≥2 已结案客户**（附录O 一）——即 N=2 是三段主线的最低生存线，N 的实际值由试点批次实测（假设 M1）。
- 方向性结论（不依赖 N 具体值）：单人审计费层定价下，收入上限为**六位数（数十万 USD 量级）封顶、不可能是七位数生意**——这是带宽不等式的结构性结果，不是努力问题。任何"单人年入千万"的排期都直接违反附录O 三硬约束⑤，应在 PRD 中以红线呈现。

### 2.4 "单人供给 vs 排队需求"核算（三硬约束③：串行不重叠）

- **供给侧**：单人终审带宽是唯一供给；多项目并行时按 C5 带宽总账合并记账，超限先降并发（元组织 C5）——即供给上限 = 同时在航项目数的饱和点，其值待 M1 实测。
- **需求侧信号**（方向性，均来自市场线核实锚点）：目标买方"持 SOC 2 Type II 年审 + ISO 42001 在途 + EU AI Act 义务主体 + 已购 agent 治理工具"（市场线·结论节一）——预算池已验证存在且持续（结论节二）；高风险合规采购窗已延长至 2027-12/2028-08（锚⑤，窗口净延长约 16 个月）——**需求窗对第一段是拉长而非缩短**。但品类直接价格证据为零（结论节执行注记 3）——"排队需求"的量化排队长度**无锚**，登记为假设 H1 的组成部分。
- **核算结论**：串行不重叠约束下，事前时间表必须过"单人供给 vs 排期需求"核算（附录O 一·三硬约束③）。在 M1 未实测前，任何多项目并行排期都只能以"待校准"状态进入 PRD；PRD 应内置降并发触发器（带宽总账超限 → 先降并发再收窄作业面，不降验证标准——元组织 C5/§6.4）。

### 2.5 R/I 抽样配额与第二判断者对排期的约束

1. **R/I 抽样配额**（附录O 三硬约束⑤原文："规模化前置=R/I 抽样配额落地"）：其操作性来源为元组织政策 `sampling-rate-explicit`（验证额度抽样率显式设定，禁止"感觉还行"——§6.1）与信任三段制（§6.4：首验全量→信任后降密度→维持期显式抽样率）。**注**："R/I"缩写在两份理论文档中未展开定义（抽样配额的具体分层口径无文档记载）——按冲突/缺口处理规则登记上浮（见第六节·上浮项 U1），不自行补写定义；其具体配额值列为假设 M3，试点批次实测。
2. **第二判断者培养**（附录O 四·死法④回填路径）：固定承担敌意审查 → 逐步接管部分终审 → 独立留痕；**12–18 个月无法就位则如实拉长至 48 个月**。对排期的三重约束：
   - 培养期与第一段（0–12 个月）几乎完全重叠——单人带宽须同时覆盖"交付 + 带教敌意审查"两线，带宽总账压力最大的时段恰是冷启动期；
   - 第二段启动 gate 含"第二判断者就位"（附录O 一）——若培养滑向 48 个月档，第二段整体顺延，三段主线的时间表按串行硬约束③联动后移，PRD 不得以乐观排期覆盖此风险；
   - 培养机制本身消耗终审带宽（复核敌意审查结论 = 判断带宽支出），即第二判断者在就位前是**带宽净消费者**——排期核算须计入。

## 三、合规面判定

**判定：可行（边界内）。**

无资质形态下"审计诊断"的占位合法性成立，但三条边界必须产品化（写入交付物命名、合同模板与监控机制）：诊断≠出证、同体分业、时间窗触发监控。

### 3.1 诊断 ≠ 出证的占位合法性边界

- **理论依据**：附录O 一——"诊断=无资质形态下唯一合法的审计占位"；出证路径只在第三段（与持牌机构合作，本方供方法论与审计引擎、持牌方出证，绕开资质墙）。
- **市场先例（锚⑧·来源 1，BABL AI）**：独立 AI 审计商已公开提供 "Conformity Assessment **Readiness/Preparation Audit**"，并明言 "no organization can obtain a Conformity Assessment"（EU AI Act 规则未终）——即"预备审计/就绪度审计"形态在市场上已有无资质供给者在合法经营，占位形态有先例。
- **产品化的合法性边界（进 PRD 的约束）**：
  1. 交付物命名限于"诊断报告 / 差距分析 / 盘点报告 / readiness review"——禁用 "certified / 合格评定 / 通过认证" 等出证性表述，也不得出具任何可供客户对外声明的"通过/符合"结论；
  2. 交付物内容是发现清单与差距（附录O 三："审计诊断卖的是**去相关检验**——独立第二双眼的发现报告，不是替客户做经营终审——终审权始终在客户"）；
  3. 若客户要求出证级结论 → 明示不在第一段服务范围，第三段路径（持牌合作）是唯一出证通道。

### 3.2 同体分业红线（安达信死法）

- **理论依据**：附录O 一·三硬约束②原文——"同体分业（同一客户不得同时购买研究与审计——审计与咨询捆绑=共享盲点，**安达信死法**，一旦曝光品牌归零）"。
- **产品化约束（进 PRD）**：
  1. 合同模板内置冲突条款：同一客户名下不得并存"研究/咨询/实施线"与"审计诊断线"两份在航合同；老客户转线须先结清并设置冷却期（冷却期时长无文档锚点，列为假设 M5，合同起草时定）；
  2. 计费结构配合：**按有效发现计费**（附录O 四·死法⑤回填"同体分业+按有效发现计费"）——计费与发现挂钩而非与客户满意挂钩，从激励上切断"讨好客户出干净报告"的腐败通道；
  3. 卖点红线联动（附录O 三）：禁"我们替你判断"，替"我们让你的判断可审计、可归因、可复用"——诊断方不进入客户经营终审席位，独立性才有物理基础。

### 3.3 监管时间窗（仅用市场线核实口径）

| 监管线 | 市场线核实口径（锚点） | 对第一段的含义 |
