## 四、攻击维度四：死法遗漏

DecisionRecord 现列 6 条死法（L67–73），含强制项"协调者自身失效"（L72，在场但充分性见 F6）。对照规范 D1–D7 与本组织特异性，遗漏如下：

**F10 [P1] 遗漏"商业前提被证伪"——杀死本组织的最短路径不在死法栏**
- 证据：死法2（L69）只覆盖"需求**无**市场锚/凭记忆引用"；P1 预测（L78）把附录O 与外部证据的口径偏差定位为"需在 PRD 中**显式呈现差异**"的常规事件；超界类（L91）提供的是记录-上浮机制而非前提级处置。而书 L5100 诚实边界明示附录O 的组织证据"全部为自产实证（现场演示级，非参考客户级）"——商业锚点本身是一步之遥的间接证据。
- 攻击：本组织真正的高代价死法是：市场线核实发现附录O 前提不成立（如买方并无已验证的 agent 审计预算、SOC 2 定价锚不迁移至 agent 组织审计品类、空窗已关闭）——此时继续产出 PRD 即为死产品写需求书。现文本下该场景的默认行为是"记录差异、继续交付"，因为没有任何条目说"差异达到什么程度时，产出 PRD 本身就是错的、应上浮 goal-keeper 裁定目标变更"。死法栏缺位 = 预演缺位。
- 修复：死法栏增列第 7 条"附录O 商业前提被外部证据证伪/部分证伪（中×高）→ 对策：波次2 前置前提复核（市场线关键锚点与附录O 逐项对账），前提级冲突即停机上浮触点③，PRD 只在前提成立或目标经人类变更后产出"。

**F17 [P2] 判断带宽记账未合并并行负载，且死法4 与 P4 口径不一**

- 修复：死法4 对策与 P4 统一口径（"目标 ≤4，含例外上限 5"）；备注"goal-keeper 为两局共享，合并记账属局级账本义务（本组织单侧无法闭合，留痕上浮）"。
