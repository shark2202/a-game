# PRD · Agent 组织审计诊断产品

**产品工作名**：AgentOrg Audit-Dx（agent 组织审计诊断）
**商业主线**：附录O 第一段（0–12 个月唯一主营收）
**goal-keeper**：人类（终审栏见§十一）

---

## 一、产品定位与商业目标

**一句话定位**：对 agent 规模部署企业做**组织级审计诊断**——覆盖四维度（AOOS 合规性 / 委托图 / 验证额度盘点 / 监督通道缺口），交付发现清单与差距报告，不做出证、不替客户终审。

**商业目标（附录O 第一段原文锚定）**：
1. 唯一主营收段（0–12 个月）；付费锚定在买方**已验证的审计/合规预算**（SOC 2 Type II 年审 $18k–90k/年、ISO 42001 首年 $20k–80k（小型组织总花费口径，见附录A）、监督审计 $3k–20k/年——证据锚点①③，读取时点 2026-09-16，市场线报告）。
2. 卖点=**去相关检验**（独立第二双眼的发现报告），不是替客户做经营终审——终审权始终在客户（附录O 三；卖点红线对照见附录B）。
3. 串行三段主线的第一段：第二段（open-core 工具）gate=本段 ≥2 已结案客户+第二判断者就位；第三段（持牌合作出证）为唯一出证通道。

**差异化定位（锚④判读，VERIFIED）**：认证覆盖 AIMS 文档与时点抽样，本产品覆盖**委托图/验证额度/监督通道的组织级盘点**——互补而非替代。"管理体系时点认证 ≠ agent 运行时持续审计"的空档经多家独立来源共认（市场线锚④）。

## 二、目标买方与市场证据

**目标买方**：已过合规成熟度门槛、agent 进生产、但组织层看不见 agent 的企业。可识别信号（每条锚定已核实证据）：

| 信号 | 证据锚点 | 核实结论摘要 |
|---|---|---|
| 持 SOC 2 Type II 年审 | ① | 典型 $18k–90k/年（boutique $7.5k 起、Big Four 至 $400k；AI/ML 行业中位 $12k–45k）；Type II 为年度重复性质 |
| ISO 42001 在途或已认证 | ③ | 首年总花费小型 $20k–80k/中型 $35k–90k；监督审计 $3k–20k/年——持续付费已开通 |
| EU AI Act 义务主体 | ⑤ | 透明度/治理/罚则 2026-08-02 起已生效；高风险义务推迟至 2027-12-02/2028-08-02（Reg (EU) 2026/1744，官方源核实）——合规采购窗净延长约 16 个月 |
| 已购 agent 安全/治理工具 | ⑧ | 四类厂商市场已成型且并购整合中——工具能见度暴露"组织层无人看全景"缺口 |
| 风险动机 | ⑥⑦ | Gartner 2025-06-25 官方预测"超 40% agentic 项目截至 2027 年底取消"，三因之一=风险控制不足；Klarna 公开实证"AI 替代过度→质量下降→回补人力"（"700"为等效工作量口径；类比级映射） |

**推断（显式标注非实证）**：最可能落点为 50–500 人 B2B SaaS/AI 公司。
**诚实边界**：品类直接价格证据为零（⑧），付费意愿为相邻预算池推断——**H1 高代价假设，试点批次实测为硬前置**（与附录O 第二段"零锚待实测"分级一致）。

## 三、MVP 边界

**做（第一段范围内）**：
- 时点诊断：四维度盘点 → 诊断报告（发现清单+差距分析+修复建议，引用条款级依据）
- 试点批次交付（首 1–2 单，含验收清单与"不达标不收费"）
- 诊断方法论与检查清单的产品化（基于元组织规范与理论现成检查物）

**不做（明确排除，每条有依据）**：
- 持续运行时监控/常驻观察——第二段 open-core 工具范围（附录O 一·第二段；产品线技术面边界）
- 任何出证性结论（certified/合格评定/通过认证）——无资质形态下不合法，第三段持牌合作是唯一出证通道（附录O 一；P0-5）
- 替客户运营/替客户终审——卖点红线（附录O 三；附录B）
- 同一客户的咨询/实施线——同体分业红线，安达信死法（附录O 三硬约束·同体分业条；P1-3）
- 人天单价报价形态——咨询陷阱死法①（附录O 四；P1-1）

## 四、产品需求（每条 P0/P1 附商业锚点+证据锚点+可判定验收标准）

**三态/等级判定 rubric（全节通用）**：{具备|部分|缺失}——具备=文档与执行证据齐备；部分=有文档或陈述、无执行证据；缺失=两者皆无。{有|部分|无}（通道类）同口径。断点风险 {高|中|低}——高=不可委托内核被委托给 AI 或治理环无承载者；中=有承载者、无证据物；低=有证据物、未演练。

## 五、可行性判定（AC2）

| 面 | 判定 | 依据摘要 |
|---|---|---|
| 技术面 | **可行**（时点诊断形态） | 四维度全部有清单级/指标级操作化锚点（元组织 §10.1/§6.1/§6.2；理论 16.2/48.6/49.5/49.7；附录F 提案三——**提案 v0.3，待人类终审、未并入正文 v1.0；其中监督三通道/执行前审 L 部分以提案文本为据，否决时回退理论正文章节等价检查物**）；检查物均为文档/配置/数据形态，不依赖运行时接入 |

### 排期与"单人供给 vs 排队需求"核算（三硬约束·串行不重叠条，附录O 5082 行）

**事前排期规则**（结构在场，数值待 M1 实测回填）：
1. **单案串行**：第一段采用单案串行交付（scoping→签约→执行→交付→验收→校准全流程完结后方接新案）；执行期并行上限=1 案。M1（单案终审人时）实测后，由带宽总账校准并行上限——校准前以最保守档（=1）运行。
2. **签约前核算（强制）**：任何新案签约前必须过"单人供给 vs 排队需求"核算并留痕——当前在航案数 + 第二判断者带教带宽占用 + 本案预估终审负载 < 带宽饱和点；核算不过则排期后移，**不得以重叠排法消化**（三硬约束·串行不重叠条原文：带宽约束杀死的不只第三段，是重叠排法本身）。
3. **三档时间表**：第二判断者培养按 12/18/48 个月三档联动（P1-4）；第一段（0–12 个月）目标达成 ≥2 已结案客户（第二段 gate），该目标本身受 M1 与 H1 实测校准——排期表数值一律"待校准"状态呈现，禁乐观单线。
4. **带宽消耗项清单**（合并记账）：交付终审 + 敌意审查结论复核 + DecisionRecord 校准 + 第二判断者带教（就位前为带宽净消费者）+ 常设监控（P0-7）。

## 六、定价框架

- **参照系**：审计费层 $5k–90k 量级（锚①③+市场线结论节二），非咨询层。
- **结构**：与"有效发现"挂钩（P1-3），禁人天单价（P1-1）；具体档位落点列 M2，首单谈判实测。
- **红线**：任何"单人年入七位数"的排期叙事直接违反三硬约束·判断带宽条，按死法预演处理（§八）。

## 七、试点设计（AC3：首个客户交付与验收流程）

**试点目标**：实测 H1（付费意愿）/H2（输入可得）/M1（单案人时）/M2（定价档位）/M3（R/I 配额口径）。
**试点数量**：1–2 单（第二段 gate 要求 ≥2 已结案客户）。

**交付流程**（每步留痕）：
1. **Scoping**（1 周，无锚假设，M1 实测回填）：四维度输入可得性核验（H2）——客户方文档/配置/数据盘点清单预检；不可得项决定访谈重建范围并标注。高代价假设按 39.6 机制交客户决策人确认。
2. **签约**：**验收清单与"不达标不收费"条款 + 留痕权与同体分业最小条款版（P0-6(c)）**；完整模板（含计费结构与冷却期）按 P1-1/P1-3 节点交付。
3. **执行**（2–4 周，无锚假设，M1 实测回填）：四维度并行盘点（AI worker 草稿 → 敌意审查复核 → 单人终审——本组织 AOOS 流程的复用，即"吃自己的狗粮"）。
4. **交付**：诊断报告（P0-1~P0-4 四模块）+ 修复优先级路线图。
5. **验收判定**：对照合同验收清单逐项判定（四维度交付物齐备/每项证据可复核/客户方可复现判定）；**未达清单 → 免收费用**，判定过程留痕。
6. **校准回填**：三字段记账 + 带宽总账读数 + DecisionRecord 校准（H1/M1/M2/M3 实测值回填本 PRD，假设清单状态更新）。
