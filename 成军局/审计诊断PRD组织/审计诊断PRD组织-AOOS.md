# 审计诊断PRD组织 · AOOS v0.2

> **Goal（Locked）**：为附录O第一段商业主线——"对 agent 规模部署企业做组织级审计诊断（AOOS 合规性 / 委托图 / 验证额度盘点 / 监督通道缺口）"——产出一份**可落地的产品需求 PRD**：完成符合商业目标的需求确定、可行性确认，PRD 含可判定验收标准、MVP 边界与试点设计。
>
> **可判定验收条件（AC，每条缺一不算完成）**：
> - **AC1 需求锚定**：PRD 需求集合中每条 P0/P1 需求均附（a）商业目标锚点——映射附录O第一段的四审计维度、三硬约束、六死法、卖点红线**之一**（开放四类锚点集）——与（b）证据锚点（外部证据须带来源+读取时点；理论依据须带文档章节锚点）。
> - **AC2 可行性判定**：PRD 含技术 / 资源 / 合规三面判定，每面为 {可行 | 有条件可行 | 不可行} + 依据清单；资源面含量化带宽核算（收入上限 = 单人终审带宽 × 费率 × 排期约束）。
> - **AC3 可落地性**：PRD 含 MVP 边界（做什么 / 明确不做什么）、**每条 P0/P1 需求**附可判定验收标准、负例、优先级排序、试点设计（首个客户交付与验收流程，含"不达标不收费"红线的落地方式）。
> - **AC4a 流程合规（verifier 波次4可判）**：AOOS 与 DecisionRecord 落盘；设计审查与 PRD 审查两份敌意审查判决留档（如判决 REWORK，修复与复审留痕）；fresh 验证报告落盘（结论为 Pre-Verified）。
> - **AC4b 流程闭环（解散时刻核销）**：人类触点齐备（必出场 3 次：分类/批准/终审；例外出场目标 ≤1 次、绝对上限 2 次，即总数 ≤5，超目标即记偏差）；校准回填完成；三字段记账完成。
>
> **负例（做了不算达成）**：PRD 无验收标准或验收标准不可判定（"提升客户满意度"类表述）；需求证据凭记忆引用（无来源 / 无读取时点 / 无文档锚点）；可行性结论无论证过程；未过人类终审即宣称 Verified；产出未落盘。
>
> **优先级**：正确性 > 判断带宽节约 > 成军速度（继承元组织规范第三章）。
>
> **边界（硬约束）**：不修改 D:\bytecoder_ai\ 下两份理论源文件（只读输入）；全部产物只写入本组织目录；外部证据仅经抓取核实后引用。**回退（条目级）**= 删除本组织目录（D:\bytecoder_ai\成军局\审计诊断PRD组织\）+ 注册表/缓存库中**本组织条目**；禁止删除成军局级目录——注册表与缓存库为服务未来目标的常设共享资产，不属本组织可回退范围（无已扩散引用：两份理论源文件只读未改）。
>
> **成军前检查**：已查注册表（D:\bytecoder_ai\成军局\注册表.md，读取时点 2026-09-16T12:33+08:00），无同目标在航组织。

## 二、Role 要点（responsibility / authority / constraints）

- **goal-keeper**：持商业目标意图，对 Type III Error 负最终责；接受/否决一切，持不可委托内核；触点出场（必出场 3 次 + 例外 ≤1 次，硬上限 5），不代行 AI 判断。
- **coordinator**：组织形成、分解委派、单写者落盘、综合；不代替下级下结论。写注册表/缓存/AOOS/任务书/运行状态/PRD；派发子代理（fresh 判定者派发经触点②确认）。禁不可逆操作；无缓存 active 化裁决权；产物经试点或 fresh 复核。
- **market-researcher**：单线"溯源→精读→落盘"，每条结论带锚点（URL + 读取时点）；只读外部源，只写自己文件。禁凭记忆引用；截断显式标注；价格 / 时间线类数字必须给出处原文口径；与附录O记载冲突时记录冲突不静默改写。报告分节带状态行（试点节 / 全量节，头部标注"已完成/进行中"）。
- **product-researcher**：可行性三面判定 + 量化依据；只读理论文档（含附录M/N/O、相关章节）与市场线报告的"证据锚点"节（定向授权：仅该节，且仅波次1c 派发后）；只写自己文件。判定只能基于文档锚点 / 已核实外部锚点 + 显式假设清单（"我替你做了哪些假设"按错误代价分级）；禁无依据结论；任务书附工艺自检 checklist（锚点格式 / 假设分级 / 判定三选一），产出前自检留痕。
- **hostile-reviewer-design**：以推翻 AOOS 设计为任务（证据 / 去重 / 可执行性 / 死法遗漏四维攻击）；只读（读域见 Actor Registry），只报告；判决三选一（ACCEPT / notes / REWORK）。
- **hostile-reviewer-prd**：以推翻 PRD 为任务，专攻：需求-商业目标锚定完整性、可行性论证链、验收标准可判定性、附录O 卖点红线是否被违反（"违宪卖点"清单）。只读（读域见 Actor Registry），只报告；判决三选一。
- **verifier**：合规审计（对照 AC1–AC4a 逐条，含 AC1(b) 文档章节锚点真实性核对）+ 数字抽查（PRD 中每个外部数字回溯证据文件核对口径）；只读（含两份理论源文件），只报告不修复；与产出者无共享上下文。

## 四、DecisionRecord（事前）

**决策**：为附录O第一段主线（agent组织审计诊断）成军"审计诊断PRD组织"，产出可落地 PRD。

**维度**：成功怎么判——见 Goal AC1–AC4a（需求锚定 / 可行性判定 / 可落地性 / 流程合规，均可逐条核对）；AC4b 为解散时刻核销项。

**死法（概率×代价，词典序）**：
1. **PRD 泛化不落地**（高×高）→ 对策：MVP 边界 + 负例 + 每条 P0/P1 需求附可判定 AC；敌意审查专攻可执行性。
2. **需求无市场锚 / 凭记忆引用**（中×高）→ 对策：市场线强制抓取核实 + 读取时点标注；verifier 数字抽查；附录O 记载冲突不静默改写。
3. **可行性走过场**（中×高）→ 对策：三面各需判定 + 依据清单；敌意审查攻击论证链；产品线假设清单按错误代价分级 + 工艺自检。
4. **判断带宽超限**（中×中）→ 对策：人类触点目标 4 次（必出场 3：分类/批准/终审；例外目标 ≤1、绝对上限 2，总数 ≤5），超目标即记偏差；PRD 一次性终审而非分批审。**备注**：goal-keeper 为两局共享（交付局在航组织"交付局设计军"亦待其终审，见第五节环境观察），监督负载合并记账属局级账本义务，本组织单侧无法闭合——留痕于注册表并上浮。
5. **协调者自身失效 / 上下文腐化**（低×高，强制预演项）→ 对策：本 AOOS + 任务书 + `运行状态.md`（波次完成清单+时戳+当前待办+actor状态，每波次收尾更新）全部落盘——新会话按 §5.3 自举协议 + 注册表"待批/在航"行 + 运行状态可完整重建**执行到哪一步**（含 1a/1b 之辨：市场线报告分节带状态行），不依赖协调者会话记忆；锚点化产物（每条结论可独立回溯）使协调者替换或会话中断不污染下游。
6. **外部抓取失败 / 截断失真**（中×中）→ 对策：降级拓扑预置（见第五节，含聚合停机阈值）；截断显式标注；全源失败项标 UNVERIFIED 上浮，不凭记忆补。
7. **附录O 商业前提被外部证据证伪 / 部分证伪**（中×高）→ 对策：波次2 前置前提复核——市场线 8 项锚点与附录O 逐项对账；前提级冲突（定价锚不迁移至 agent 组织审计品类 / 空窗已关闭 / 买方并无已验证的 agent 审计预算）即**停机上浮触点③**，PRD 仅在前提成立或目标经人类变更后产出——禁止"记录差异、继续交付"的默认路径接管前提级处置。

**可逆性（条目级）**：回退 = 删除本组织目录（D:\bytecoder_ai\成军局\审计诊断PRD组织\）+ 注册表/缓存库中本组织条目；禁止局级目录删除（共享注册表/缓存库为常设资产）。无已扩散引用（两份理论源文件只读未改）。

**事前 Prediction（可判定断言）**：
- P1：市场线核实的 **8 项**（任务书钉扎清单，项数固定）外部锚点中，至少 1 项与附录O记载存在口径偏差（价格区间 / 时间线 / 表述），需在 PRD 中显式呈现差异。
- P2：可行性资源面结论为"有条件可行"，条件含第二判断者培养与 R/I 抽样配额机制前置（附录O 死法④的镜像）。
- P3：敌意审查（PRD）至少触发一次 REWORK，或触发导致任一 P0 需求变更 / 可行性结论翻转的 notes（"重大"以此判定，口径钉扎）。
- P4：全流程人类触点实际出场 = 必出场 3 次（分类/批准/终审）+ 例外 0–2 次（预期 0–1 次）；总数 >4 即"带宽挤压"预警命中，=5 为绝对上限（口径与死法 4 / AC4b 统一）。
- P5：市场线外部证据中"竞争格局"（第⑧项）的公开可得性最低（agent 组织审计为新兴品类，直接对标者可能稀少），预期以相邻品类（AI 治理审计 / 传统 SOC 2 咨询）替代映射，需显式标注替代口径。

## 五、Runtime Loop（含降级拓扑预置）

标准 AOOS 循环：Goal → 分析需求 → 选 Actor → 授权 → 成军 → 执行 → 验证 → 学习 → 重构。
